# Pamieć wspólna

### **Mapowanie pamięci**

`mmap` - prosi jądro o zarezerwowanie przestrzeni adresowej danego rozmiaru, i powiązanie go z konkretnym plikiem, lub czystą pamięcią `MAP_ANONYMOUS`

- program rezerwuje sobie w pamięci RAM przestrzeń adresową zwaną mapą
- mówi ona gdzie znajduje się kod programu, zmienne, stosy
- a mapowanie plików zajmuje wolne obszary tej przestrzeni
- to jak wygląda ta mapa znajduje się w `/proc/<PID>/maps`

`munmap()` - usuwanie mapy

### **Rodzaje mapowań**

Flagi `mmap()`:

- `MAP_SHARED` - inne procesy mogą widzieć zmiany w pliku od razu, a program zapisze je w pliku
- `MAP_PRIVATE` - orginalny plik pozostaje nie tknięty, program tworzy kopię części pliku w której chce dokonać zmiany, zmiana nie jest zapisywana do oryginalnego pliku, można porównać do `fork()`
- `MAP_ANONYMOUS` - dostajesz czystą pamięć

### **Ochrona zmapowanej pamięci (Prawa dostępu)**

Flagi `mmap()`:

- `PROT_READ` czytanie
- `PROT_WRITE` zapisywanie
- `PROT_EXEC` uruchamianie
- `PROT_NONE` zakaz wstępu

### **Synchronizacja RAM z dyskiem**

`msync()` funkcja zarządzająca synchronizacją

Flagi `msync()`:

- `MS_ASYNC` planuje zapis w wolnej chwili, wywoluje proces asynchroniczny, ktory nie blokuje dzialania programu
- `MS_SYNC` zatrzymuje program i czeka aż zapisze

### **Komunikacja międzyprocesowa IPC**

`fork()` wywołuje proces potomny który współdzieli pamięć, `mmap()` dyktuje jednak jak jest ona wykożystywana

Flagi `mmap()`:

- `MAP_SHARED` natychmiast widoczne, w pełni sharowane
- `MAP_PRIVATE` **COW**, zmiany są wykonywane na prywatnej kopi, nie są współdzielone ani zapisywane

### **Obiekt pamięci współdzielonej POSIX**

POSIX wprowadza abstrakcyjny obiekt pamięci współdzielonej, który można traktować jako plik, jest on jednak obecny w pamięci RAM

Cykl życia obiektu pamięci współdzielonej:

1. `shm_open(name, flags, mode)` otwiera (tworzy jeśli nie ma) obiekt
2. `ftruncate(fd, length)` ustalanie rozmiaru obiektu pamięci
3. `mmap()` mapuje obiekt w pamięci ram, według odpowiedniej flagi
4. `shm_unlink(name)` usuwa dostęp do pliku dla danego procesu, jednak może on nadal istnieć trzymany przez inny proces, gdy nie wywołamy tej funkcji obiekt **SHM** będzie żył do restartu systemu

### **Przestrzeń nazw SHM**

Wszystkie obiekty pamięci współdzielonej są widoczne w wirtualnym systemie plików `tmpfs` w katalogu `/dev/shm/`
Można zarządzać obiektami **IPC** za pomocą standardowych komend jak `ls` czy `rm`

`MAP_ANONYMOUS` nie powiązuje żadnego pliku ani obiektu w `/dev/shm/` (nie istnieje on w tym katalogu), nie trzeba się martwić o usuwanie

## Słowniczek

**IPC** - **Inter Process Communication**, mechanizmy pozwalające różnym procesom na dzielenie się danymi w trakcie ich działania

**COW** - **Copy On Write**

**SHM** - **Shared Memory**

**POSIX** - **Portable Operating System Interface**

**tmpfs** - **TeMPorary File System**
